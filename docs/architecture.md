# 架构与维护

MergeLane 是一个二进制 crate，入口为 `src/main.rs`。每位团队成员在自己的开发机启动一个进程，通过 MCP 将任务平台接入自己的 Agent。团队的任务、分工、依赖和进度保存在现有实例中，各进程通过读取同一实例取得共享状态。

运行方式包括 MCP stdio 服务、Gitea 工单上下文查询和 Gitea 变更监听。当前只需要一个 crate，不需要独立数据库或后台服务。

## 模块边界

| 模块 | 职责 |
| --- | --- |
| `main` | 命令分发、进程启动和监听退出 |
| `cli` | Clap 参数、环境变量和已配置后端的构建 |
| `credentials` | 凭据文件大小、权限和内容读取 |
| `settings`、`settings::storage` | 版本化个人配置、校验、相对路径、锁和原子更新 |
| `setup` | init 交互、逐平台配置和客户端片段生成 |
| `cli::profile` | 将配置展开为参数再交给 Clap，保持参数校验与优先级 |
| `doctor` | 只读凭据及账号连接检查、JSON 结果与失败退出码 |
| `mcp` | 按行 JSON-RPC 输入输出、初始化、共用参数与 schema 构建、后端分发 |
| `lease` | 按实例及工单 ID 识别任务，共享本地租约，续租和检查点校验 |
| `validation` | 后端共用的纯文本校验，不依赖网络和具体平台 |
| `issue` | 单张工单创建、指派和编辑的参数、校验与工具描述 |
| `tracker`、`tracker::plan`、`tracker::write` | GitHub、GitLab、Jira 共用的工具、预览、任务发布、依赖补齐和检查点恢复 |
| `tracker::http` | 新 REST 后端共用的认证、有界响应、分页和实例路径校验 |
| `github`、`gitlab`、`jira` | 各自的身份、查询、API 路径、链接和原生依赖语义 |
| `jira::text` | ADF 与纯文本转换，保留恢复标记的段落边界 |
| `gitea` | Gitea HTTP 边界、工单上下文、阻塞关系、评论和文件元数据 |
| `gitea::mcp`、`gitea::plan` | Gitea 工具、会话内预览、草稿规范化、任务和依赖校验、计划 ID |
| `gitea::references` | 工单链接、仓库名、固定提交文件链接和路径校验 |
| `gitea::search`、`gitea::write` | 工单搜索，以及任务、依赖、计划汇总和检查点的发布 |
| `gitea::watch` | 轮询指定工单并输出变化，不持有额外的团队状态 |
| `plane` | Plane HTTP 边界、工单上下文、成员、状态、关系和游标分页 |
| `plane::mcp`、`plane::plan` | Plane 工具路由、会话内预览和异步成员校验 |
| `plane::references`、`plane::search`、`plane::write` | 链接解析与 HTML 转义、搜索与成员解析、发布与恢复 |
| `plane::checkpoint` | 评论正文、父工单预览校验和子工单进度发布 |

Plane 可以单独运行。额外配置 Gitea 后，Plane 上下文读取会复用 Gitea 文件版本检查。两者保留独立凭据、写入开关及最新计划预览。

后端会话拥有自己的预览状态，公共 MCP 层通过 `new`、`tools`、`call` 使用会话，不直接读写其内部字段。普通文本校验通过 `validation` 共用，Plane 只有在需要 Git 文件跟踪时依赖 Gitea 的实际能力。

## 扩展其他后端

GitHub、GitLab、Jira 的共同工作流已提取为 `tracker::Api` 和 `tracker::Session<A>`。平台适配器处理真实 API 差异，会话拥有独立写入开关和最新预览。Gitea／Plane 保留既有计划格式与 Git 文件跟踪能力。增加其他平台时，改动位置应当可预测：

1. 在 `src/<backend>.rs` 和必要的子模块实现 `tracker::Api`，处理 API、链接、成员、查询和依赖；共用 `tracker::Session` 的工具与预览，保持 `<backend>_*` 命名空间。确有不同协作语义时再增加独立会话。
2. 在 `cli` 中增加连接参数、环境变量和独立写入开关，凭据文件继续交给 `credentials` 读取。
3. 在 `tracker::Backends` 接入新会话的构造、工具列表和调用分发，并在公共 `mcp` 层注册命名空间。协议解析、输入帧和 JSON-RPC 错误仍在公共层处理。
4. 在该平台的适配层处理成员身份、任务关系、分页和状态。平台能力差异应在工具与接入文档中说明；不要把其他平台的专属格式传播到公共协议层。
5. 明确确定性标记、部分失败后的恢复方式与并发发布限制。发布前保留预览和确认检查，不能仅凭工具名或 MCP 注解判断安全性。
6. 使用本地模拟 API 与真实二进制补充集成测试，验证独立配置、联合配置、写入隔离和失败恢复，再增加接入文档和配置参考。

公共 trait 只覆盖已经由三个 REST 实现验证的协作语义。平台的特殊字段、父子层级、审批、状态流转和文件版本比较不会被假定为相同能力；新增能力时先核对适配器实际支持范围。

## 一次计划的生命周期

1. Agent 从工单上下文中取得需求、成员和阻塞关系。
2. `*_preview_plan` 校验并规范化草稿，生成确定性的计划 ID。每个后端在当前 MCP 会话中只保留最新预览；此阶段不写远端。
3. 用户审阅后，调用方通过 `*_apply_plan` 传入匹配的 `plan_id` 和 `confirmed: true`。进程必须已开启对应写入开关，账号也必须具有远端权限。
4. 创建或找到已有任务，核对负责人，补依赖，最后在总工单发布汇总。
5. `*_checkpoint` 在确认后写入远端评论。后续会话重新读取工单即可接手；本地预览不会跨进程保留。

Gitea 通过工单正文中的 `mergelane:task`、评论中的 `mergelane:plan` 标记识别已发布结果；Plane 使用 `external_source=mergelane` 和确定性的 `external_id`。这些标记是恢复协议的一部分。GitHub／GitLab 通过正文标记查找任务，Jira 通过 label 搜索并核对描述首行；评论均使用首行标记。Jira 的搜索索引存在延迟，创建结果不确定时须先检查并等待可见，不自动重试创建。计划内容变化会生成不同 ID，不应把修改后的计划当作原计划重试。

写入不具有事务回滚或并发发布锁。部分请求失败时，远端可能已经保存数据。更换会话后，先预览原样计划，再继续发布。同一计划由一位负责人提交。Gitea 用计划 ID 搜索候选工单并核对正文首行，工单改名后也可通过该标记恢复。单张工单编辑只提交调用方提供的字段，替换描述时保留恢复标记。并发编辑同一字段时由远端平台处理。

本地领取使用平台、配置的实例根地址和工单稳定 ID 生成任务键。各 MCP 进程对同一任务使用同一个 OS 文件锁，在锁内检查旧记录并原子替换。释放会保留已失效记录，避免缺失或过期的 ID 绕过检查点校验。对同一任务，MergeLane 在持锁期间等待检查点请求完成，其他本地会话可随后重试。远端超时后写入是否已生效仍需在工单中核对。

Plane 父工单检查点的预览 ID 绑定父子工单及评论正文。发布时重新读取子工单的指派和父子关系，校验预览后使用该 ID 恢复评论写入。本地租约校验使用子工单的任务键。

## 配置与 I/O

连接配置由 CLI 参数、版本化个人配置或环境变量提供，优先级依次降低；没有 dotenv 加载器。`init` 保存平台元数据与 token 路径，不复制 token 内容；`doctor` 只读检查账号连接，不能证明项目写入权限。token 文件限制为不超过 4096 字节的普通文件，在 Unix 上拒绝组和其他用户的访问权限。代码中不存放真实凭据。变量、命令与排错入口见 [配置参考](configuration.md)。

HTTP 客户端禁用重定向，Gitea 请求超时 20 秒，Plane 为 25 秒。每个响应限制为 1 MiB，MCP 输入帧限制为 512 KiB。URL 解析和 API 路径构建集中在各自适配层。标准输出专用于 MCP JSON-RPC 或 CLI JSON，新增日志应使用标准错误。

工单与评论是远端项目数据，不是给 Agent 的可信指令。写入参数中的确认标记由调用方提供，无法替代客户端的人工审批。完整安全边界见 [SECURITY.md](../SECURITY.md)。

## 文件版本跟踪

每张工单最多读取八个去重后的同实例 Gitea 固定提交文件链接。工具并行读取基线和默认分支上的文件元数据，用 Git blob SHA 判断内容是否相同。输出状态为 `current`、`needs_review` 或 `unavailable`，附固定版本链接；它不修改源码或自动更新工单中的基线。

## 验证范围

`src/gitea/references.rs` 和 `src/plane/references.rs` 中的单元测试覆盖链接解析与不可信文本处理。公共 `mcp` 测试验证后端工具列表、独立写入开关以及发布前的确认和预览要求。

`tests/gitea.rs`、`tests/plane.rs`、`tests/trackers.rs` 启动假 HTTP API 和真实 MergeLane 子进程，覆盖 MCP 查询、预览、确认、发布失败后恢复、共享上下文及资料变化。`tests/support/mod.rs` 共用 MCP 子进程通信与假凭据文件创建，统一清除个人后端环境配置，并在句柄释放时终止子进程。

这些测试不证明真实服务所有版本或所有 MCP 客户端均兼容。接入文档记录实例要求与已有验收范围；变更协议或第三方接口时，应在专用测试实例补充验收并记录实际版本。
